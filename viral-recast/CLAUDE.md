# CLAUDE.md(viral-recast)

このフォルダは、Claude Code が **Higgs Field**(MCP ツール群: `mcp__higgs_field__*`)を使って
「すでにバズった動画の構成・動き・演出はそのままに、登場する人物や動物などを差し替えた動画」
を制作するためのガイドです。このフォルダ内の作業では、ルートの `CLAUDE.md` よりも
本ファイルの指示を優先します。

## 基本ルール

- **返答はすべて日本語で行う。** 説明・確認・エラー報告・コミットメッセージの本文も日本語とする。
- **Higgs Field で画像・動画・音声を生成する前に、必ずユーザーの許可を取る。**
  - 対象: `generate_image` / `generate_video` / `generate_audio` / `*_batch` /
    `motion_control` / `execute_preset` / `ai_influencer_generate` / `upscale_*` /
    `reframe` / `outpaint_image` / `remove_background` / `voice_change` / `dubbing` など、
    クレジットや処理時間が発生するツールすべて。
  - 許可を取る際は「何を・どのモデルで・何本・想定コスト(`get_cost: true` で事前確認)」を
    一言で提示し、ユーザーの明示的な OK を待ってから実行する。
  - 一度許可を得ても、内容・本数・モデルが変わる場合は改めて確認する。
  - 分析(`video_analysis_*`)、アップロード(`media_upload_widget` / `media_import_url`)、
    参照エレメント登録など課金のない準備作業は確認不要。ただし迷ったら確認する。
- **クレジット消費を抑える。** 可能な限り `use_unlim: true` を使う。無制限枠が使えない旨が
  返ってきたら、「クレジットを消費するが進めてよいか」を必ず確認してから進める。

## このフォルダの目的

AI でリアルな人間(および動物など)が登場する縦型ショート動画を作る。
具体的には、参考にするバズ動画の

- カット割り・尺・テンポ
- 人物の動き・ポーズ・表情の流れ(モーション)
- カメラワーク・構図・ロケーションの雰囲気
- フック(冒頭1〜3秒)とオチの構成

を維持したまま、**登場する人物・動物・商品などを別の被写体に差し替えた動画**を作る。

## 権利・倫理面のルール(必ず守る)

- **元動画の権利**: 素材にする元動画は、ユーザー自身が撮影したもの、権利者から許諾を
  得たもの、または利用規約上リミックスが認められているものに限る。他人の投稿動画を
  そのまま転載・改変して自分の作品として投稿する形は避け、「構成・動き・演出の型を
  参考にして新規に作る」方向を基本とする。判断がつかない場合はユーザーに確認する。
- **差し替え後の人物**: 実在の人物(有名人・一般人を問わず)の顔や声を本人の同意なく
  使わない。基本は AI 生成のオリジナル人物、または同意を得た出演者を使う。
- **元動画の出演者になりすまさない**: 元の投稿者・出演者と誤認させる表現(同じ名前、
  ロゴ、アカウント表記、透かしの残存など)は残さない。
- **AI 生成の表示**: 投稿先(TikTok / Instagram / YouTube)の AI 生成コンテンツ表示ルールに
  従い、必要に応じて「AI生成」ラベルを付けるようユーザーに案内する。
- 未成年に見える人物の性的・暴力的な表現、誤情報や詐欺に使える内容は作らない。

## 生成前の台本・絵コンテ(必須・ユーザー指定)

意図と違う動画を作らないため、**動画生成の前に必ず次の2つを作り、ユーザーの OK をもらう**。
OK が出るまで生成の許可を求めない。

1. **台本(文字)** — `prompts/<案件名>/script.md`
   - 企画の趣旨を1行で書く(例: 「登り坂で動けなくなったクレーンを、坂の上の犬が引き上げる」)
   - 「絶対に守る条件」を表にする: 坂やカメラの**向き**、被写体の**形・部品**(例: クレーンのブーム)、
     数、天気など、取り違えると趣旨が壊れる要素を具体的に書く
   - カットごとに「秒・画角・映るもの・カメラの動き・音」を書く
   - 否定的・曖昧な書き方(「縮めた」「控えめ」など)で、必要な部品が消えないように注意する
2. **絵コンテ(画像)** — **無料ツール**(Pillow など、ローカルで描けるもの)で描く。
   Higgs Field などクレジットを使うツールで絵コンテを作らない
   - 1コマ=1カット、縦型なら 9:16 の枠で描く
   - 画角、被写体の位置と向き、カメラの動き(矢印)、坂などの上下関係を描く
   - 各コマの右上に「位置関係図(カメラ・被写体・地形)」を入れる
   - 描画スクリプトは `prompts/<案件名>/storyboard.py` にコミットし、画像は
     `storyboards/` に出力する(画像は git 管理外)
   - 描いたら自分でも画像を開いて、台本と矛盾していないか確認してから見せる

プロンプトは、OK が出た台本の「絶対に守る条件」と「カット表」をそのまま英語にして作る。

## 標準ワークフロー

1. **元動画の取り込み**
   - URL がある場合は `media_import_url`、ローカルファイルは `media_upload_widget` を
     最初に呼んでアップロードする(ファイルパスを直接扱わない)。
2. **元動画の分析(課金なし)**
   - `video_analysis_create` → `video_analysis_status` でカット構成・尺・動き・
     カメラワークを分析し、`prompts/<案件名>/analysis.md` に要点をまとめる。
   - 必要に応じて `virality_predictor` でフックの強さや離脱ポイントを確認する。
3. **差し替え対象の準備**
   - 差し替え後の人物/動物の参照画像を用意する。
     - 同一人物を複数カットで使い回す → `show_characters`(Soul、5〜20枚、
       `soul_2` / `soul_cinematic` 専用)または `show_reference_elements`(即時利用、
       複数被写体OK、他モデルでも使える)。
     - 新しい AI 人物をゼロから作る → `ai_influencer_prepare` で設計と見積もりを出し、
       **許可を得てから** `ai_influencer_generate`。
4. **ワークフローの選択**(必ず事前にカタログを確認し、憶測で決めない)
   - 引数なしで `get_workflow_instructions` を呼び、存在するワークフローを確認する。
   - 既存クリップの人物・商品の差し替え(4〜30秒) →
     `get_workflow_instructions({ workflow: "ad-multiplier" })` を読み込んで従う。
   - 1カットの動きを別キャラに移す(モーション転写) → Genjutsu の
     `hf_mult_motion_control`(`generate_video` 経由)。単一キャラの Kling リキャストは
     `motion_control`。
   - 映っている物体だけを置き換える → Genjutsu の `hf_mult_replace_object`。
   - トレンドの Genjutsu を使う場合は先に
     `get_presets({ source: "genjutsu", category: "genjutsu-trending" })` を確認する。
   - モデル選定に迷ったら `models_explore({ action: "recommend" })`。
5. **生成前の確認(必須)**
   - `get_cost: true` でコストをプレフライトし、内容・本数・コストを提示して許可を取る。
6. **生成と確認**
   - 許可後に生成。複数本の独立した生成は `*_batch` → `jobs_wait` →
     `show_generation_by_ids` でまとめて表示する。
   - 元動画と並べて、動き・尺・構図の再現度、人物の自然さ(手・顔・肌・まばたき)を確認し、
     問題があれば修正案を出す(再生成も事前に許可を取る)。
7. **仕上げ(いずれも実行前に許可を取る)**
   - 字幕: `subtitles` ワークフロー / サムネイル: `thumbnail-generation` ワークフロー /
     高画質化: `upscale_video` / 比率変更: `reframe`。

## リアルな人物表現のコツ

- プロンプトには年齢層・体型・肌質・髪型・服装・照明・レンズ感(例: スマホ撮影風、
  自然光、軽い手ブレ)を具体的に書き、元動画の撮影環境に寄せる。
- 「完璧すぎる肌」「不自然に整った背景」は AI 感が出やすい。UGC 風なら生活感を足す。
- 同じ人物を複数カットで使う場合は、必ずキャラクター/参照エレメントを固定し、
  シード値も記録しておく。
- 動物の差し替えは、元動画の被写体と体格・動きの近い種を選ぶと破綻しにくい。

## 出力形式のデフォルト

- SNS ショート向けは `aspect_ratio: "9:16"` を明示する。横型が必要な場合のみ `16:9`。
- 尺は元動画に合わせる。

## フォルダ構成

```
viral-recast/
├── CLAUDE.md                 # 本ファイル
├── prompts/<案件名>/         # 分析メモ・プロンプト・台本・使用した設定(シード等)
├── assets/source/            # 元動画・参照画像(git 管理外)
└── assets/output/            # 生成物(git 管理外)
```

- 生成物・素材のバイナリはコミットしない(`viral-recast/.gitignore` で `assets/source/`・
  `assets/output/` を、ルートの `.gitignore` で動画/画像拡張子を除外済み)。
- 案件ごとに `prompts/<案件名>/` を作り、元動画の出典・権利確認の状況・使用プロンプト・
  モデル・シード・生成ID を `notes.md` に残して再現できるようにする。
