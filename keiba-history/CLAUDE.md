# CLAUDE.md — 競馬の歴史・名馬の経歴動画プロジェクト

このファイルは、Claude Code が `keiba-history/` フォルダで作業する際のガイドです。
リポジトリ直下の `CLAUDE.md` の共通ルールも引き続き適用されます。内容が食い違う場合は、
このフォルダ内の作業についてはこのファイルを優先します。

## 返答のルール

- **ユーザーへの返答はすべて日本語で行う。** 質問・確認・進捗報告・完了報告も含む。
- プロンプト本文など、モデルへの入力は英語の方が精度が出る場合は英語で書いてよいが、
  ユーザーに見せる説明は日本語で添える。

## プロジェクト概要

**Higgs Field**(MCP ツール群: `mcp__higgs_field__*`)で AI 動画を生成し、
**編集(つなぎ・ナレーション・BGM・字幕・書き出し)まで**を一貫して行うプロジェクトです。

- **テーマ**: 競馬の歴史、有名馬(名馬)の経歴・ドキュメンタリー風動画
  - 例: 競馬の起源とサラブレッドの誕生 / 日本競馬の歩み / 三冠馬の物語 /
    伝説のレース再現 / 引退後・種牡馬としての功績
- **映像の方向性**: **AI によるリアルな人間の映像**を中心に据える。
  騎手・調教師・厩務員・観客・ナレーター(語り部)など、実写と見紛うリアルな人物描写と、
  リアルな競走馬・競馬場の映像を組み合わせたドキュメンタリー調に仕上げる。
- **主な配信先**: YouTube(横型 `16:9` の長尺)と、YouTube Shorts / TikTok / Instagram Reels
  (縦型 `9:16` のショート)。企画ごとにどちらかを決め、生成時に `aspect_ratio` を明示する。

## Higgs Field の実行ルール(ユーザー指定・2026-10-24 更新)

- **生成・加工のたびにチャットで許可を求めない。** ユーザーから「いちいち許可を求めなくて大丈夫、
  全て実行して」と指示済み。Higgs Field のツール(`mcp__higgs_field__*`)は
  `.claude/settings.json` で許可済みなので、そのまま実行してよい。
- この指示はリポジトリ直下 `CLAUDE.md` の「生成前に一言確認する」ルールより優先する
  (このフォルダの作業に限る)。
- ただし、クレジットの使い方には引き続き気を配る:
  - 同じ内容の作り直しを繰り返さない。生成前にプロンプト・尺・参照画像を見直す
  - 完了報告では、使ったクレジットの概算と残高を伝える
  - 1本の動画で 300 クレジットを超えそうな場合だけは、事前に一言伝える

## 制作フロー

1. **企画・リサーチ**
   - テーマ(時代・馬・レース)を決め、史実を確認する。年号・レース名・着順・血統・騎手名などは
     必ず出典を確認し、`docs/research/` にメモと出典 URL を残す。不確かな情報は「諸説あり」と明記するか使わない。
2. **台本・構成**
   - `scripts/<企画名>.md` にナレーション原稿とカット割り(カット番号・秒数・映像内容・テロップ)を書く。
   - 目安: ショートは 30〜60 秒・6〜10 カット、長尺は 5〜10 分。
3. **プロンプト作成**
   - `prompts/<企画名>/` にカットごとの画像・動画プロンプトを保存する(再現性のため)。
   - 時代考証を入れる(例: 1900 年代初頭の競馬場、昭和の東京競馬場、モノクロ/セピア調など)。
4. **ワークフロー確認**
   - 複数ステップの制作では、生成前に `mcp__higgs_field__get_workflow_instructions` を
     引数なしで呼んでカタログを確認し、該当するものをロードする。憶測で決めない。
   - どのモデルが適切か迷う場合は `models_explore(action: "recommend")` を使う。
5. **素材生成(※許可を取ってから)**
   - キーフレーム画像 → 画像から動画(image-to-video)の順で作ると構図が安定しやすい。
   - 同一人物(語り部・騎手役など)を複数カットで使う場合は、先に
     `show_reference_elements`(Elements)または `show_characters`(Soul)で人物を固定する。
     複数カットでの顔・服装・勝負服の一貫性を最優先する。
   - 複数の独立した生成は `*_batch` → `jobs_wait` → `show_generation_by_ids` でまとめて扱う。
6. **編集**
   - ナレーション: `generate_audio` / `create_voice` で作成(※許可を取ってから)。
   - 字幕: `subtitles` ワークフローでハードサブを焼き込む。
   - 画質・比率調整: `upscale_video` / `reframe`(※許可を取ってから)。
   - カットのつなぎ・BGM・テロップ・トランジション・書き出しは、ローカルの `ffmpeg` などで行う。
     編集手順は `edit/<企画名>/` にスクリプト(例: `build.sh`、ffmpeg の concat リスト)として残し、
     誰が実行しても同じ完成品になるようにする。
7. **確認・書き出し**
   - 完成動画は `assets/output/<企画名>/` に書き出す。必要に応じて `virality_predictor` で
     フック・離脱リスクを確認し、`thumbnail-generation` ワークフローでサムネイルを作る(※許可を取ってから)。

## リアルな人物・実在の馬に関する注意

- **実在の人物(騎手・調教師・馬主など)の顔や容姿をリアルに再現しない。**
  人物は AI で生成した架空の人物として描写し、「再現映像」「イメージ映像」であることを
  動画内のテロップや概要欄で明示する。実在人物の写真からの生成は本人の同意があるものに限る。
- 実在の名馬は、毛色・流星などの特徴を史実に寄せて描写してよいが、実際のレース映像や
  報道写真をそのまま素材として取り込まない(著作権に配慮)。
- 実在の勝負服、競馬場のロゴ、主催者の商標などは、誤認を招く形で使わない。
- 史実と異なる演出(脚色)を入れる場合は、ナレーションやテロップで脚色であると分かるようにする。

## 出力形式のデフォルト

- ショート: `aspect_ratio: "9:16"`、長尺: `aspect_ratio: "16:9"` を必ず明示する。
- 生成前に `get_cost: true` でコストをプレフライトし、可能な限り `use_unlim: true` を使う。
- Kling 4.0 の動画は `resolution: "720p"` で作る(ユーザー指定・2026-10-29)。1080p(1秒3.25クレジット)より安い(1秒2.25クレジット)。

## フォルダ構成

```
keiba-history/
├── CLAUDE.md            # このファイル
├── docs/
│   └── research/        # 史実リサーチメモ・出典
├── scripts/             # ナレーション原稿・カット割り
├── prompts/             # カットごとの画像/動画プロンプト
├── edit/                # 編集スクリプト(ffmpeg など)
└── assets/
    ├── source/          # アップロード元素材(git 管理外)
    └── output/          # 生成物・完成動画(git 管理外)
```

- 生成された画像・動画・音声ファイルは git にコミットしない(リポジトリ直下の `.gitignore` で除外済み)。
- コミットするのはリサーチメモ・台本・プロンプト・編集スクリプトなど、再現可能なテキスト資産のみ。
