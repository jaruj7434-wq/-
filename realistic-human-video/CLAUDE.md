# CLAUDE.md — リアル人間動画 × ファッション × Blender モーション

このフォルダ(`realistic-human-video/`)で作業する際の Claude Code 向けガイドです。
ルート の `CLAUDE.md` の内容も引き続き有効ですが、**このフォルダ内ではこのファイルの
ルールを優先**します。

## 返答言語

- ユーザーへの返答・説明・確認はすべて **日本語** で行う。
- 生成プロンプト本文は、モデルの精度を優先して英語で書いてもよい(その場合も説明は日本語で添える)。

## プロジェクトの目的

Higgs Field(MCP ツール群: `mcp__higgs_field__*`)を使い、**AI でリアルな人間の動画**を
制作する。このフォルダで作る動画は以下の3条件をすべて満たすことを基本とする。

1. **リアルな人間**: 実写と見分けがつかないフォトリアルな人物。アニメ調・3DCG調・
   イラスト調の人物は作らない(Blender の素体はあくまで「動きの参照」であり、
   最終出力には残さない)。
2. **Blender で作った動き**: 人物の動作・カメラワークは Blender で作成したモーションを
   参照として使い、Higgs Field 側でリアルな人物に置き換える(モーショントランスファー)。
3. **ファッション要素を必ず入れる**: すべての動画に、服・靴・バッグ・アクセサリー・
   ヘアメイクなどのファッション要素を**主役または明確な見どころ**として入れる。
   企画・プロンプトの段階で「どのファッション要素を見せるか」を必ず明記する。

主な配信先は Instagram Reels / TikTok / YouTube Shorts などの縦型ショート動画。

## 最重要ルール: 生成前に必ず許可を取る

- `generate_image` / `generate_video` / `generate_audio` / `*_batch` /
  `execute_preset` / `upscale_*` / `outpaint_image` / `reframe` / `motion_control` /
  `generate_3d` など、**画像・動画・音声を作成するツールは、実行前に必ずチャットで
  ユーザーの許可を取る**。許可が出るまで作成に入らない。
- 確認時には次の内容を日本語で簡潔に提示する:
  - 何を作るか(画像/動画、カット数、秒数、アスペクト比)
  - 使用モデル・ワークフロー
  - プロンプトの要点(人物像・ファッション要素・動き)
  - 想定コスト(可能なら `get_cost: true` でプレフライトした結果)
- 1回の許可は、そのとき提示した内容にのみ有効。内容・本数・モデルを変える場合は
  改めて許可を取る。
- 課金のない準備作業(`media_upload_widget`、`video_analysis_*`、
  `show_reference_elements` の閲覧、`models_explore`、`get_workflow_instructions` 等)は
  許可なしで進めてよい。ただし判断に迷う場合は確認する。

## クレジットの扱い

- 生成時は可能な限り `use_unlim: true`(無制限/トライアル枠)を使う。
- 無制限枠が使えない旨がツールから返ってきた場合は、**「クレジットを消費する形に
  なりますがよろしいですか?」と必ず確認**してから進める。無断で消費しない。

## 標準ワークフロー

### 1. 企画(`prompts/` に記録)

`prompts/<案件名>.md` に以下をまとめてから着手する。

- コンセプト・尺(秒数)・配信先・アスペクト比(基本 `9:16`)
- 出演人物の設定(年齢感・雰囲気・髪型など)
- **ファッション要素**(アイテム名、色、素材、ブランド/商品写真の有無、見せ場のカット)
- 動きの内容(歩く・回る・ポーズ・カメラの寄り引きなど)
- ロケーション・ライティング

### 2. Blender でモーションを作る(`blender/`)

- Blender でリグ付き素体(マネキン/グレーボディ)にアニメーションを付け、
  最終動画と同じアスペクト比(縦型なら 1080×1920)・フレームレートでレンダリングする。
- モーショントランスファーの精度を上げるため:
  - 全身がフレーム内に収まる、シルエットが分かりやすい背景・ライティングにする。
  - 手足が大きく重なる・高速すぎる動きは避ける。
  - 服のなびきや揺れを見せたいカットは、動きに「溜め」と余韻を入れる。
- `.blend` ファイルや Python スクリプト(`bpy`)は `blender/` に置く。
  再現用のスクリプトはコミット、`.blend` やレンダリング動画は git 管理外。
- Higgs Field の 3D シーンビルダー(`scene_builder_3d_*` ツール)で Blender 互換の
  シーンを組む・`.blend` を取得することもできる。使う場合も課金有無を確認し、
  疑わしければ許可を取る。

### 3. リアルな人物・ファッションの準備

- 同じ人物を複数カットで使う場合:
  - `show_characters`(Soul): 同一人物の写真5〜20枚で学習。`soul_2` / `soul_cinematic` 専用。
  - `show_reference_elements`(Elements): 即時利用可、複数人物・商品もOK。
- 商品(服・靴・アクセサリー)の写真は Elements として登録し、見た目の一貫性を保つ。
- まず静止画でキャラクター × 衣装のキービジュアルを作り、OK をもらってから動画化する
  (静止画生成の前にも許可を取る)。
- ローカルの画像・動画(Blender のレンダリング含む)は、ファイルパスを直接扱わず
  **必ず `media_upload_widget`** でアップロードする。

### 4. 動画化(モーショントランスファー)

- Blender のモーション動画 + キービジュアル(人物×衣装)を使い、
  `generate_video` でモーショントランスファーを行う(Genjutsu の
  `hf_mult_motion_control` 経由。旧 `motion_control` や `ad-multiplier` は1本の
  モーション転写には使わない)。
- 複数ステップの動画(UGC風・広告・ルックブック等)は、生成前に
  `get_workflow_instructions` をまずは引数なしで呼び、該当ワークフローを確認する。
  関連しそうなもの: `ugc-try-on-video`、`product-photoshoot`、`character-sheet`、
  `subtitles`、`thumbnail-generation` など(実在するかは毎回カタログで確認)。
- モデル選びに迷ったら `models_explore(action: "recommend")` で確認する。
- 出力は基本 `aspect_ratio: "9:16"`。横型が必要なときのみ `16:9`。

### 5. 仕上げ

- 必要に応じて `upscale_video`、字幕(`subtitles` ワークフロー)、サムネイル作成を行う
  (いずれも実行前に許可を取る)。
- 完成したら、使ったプロンプト・モデル・設定・生成IDを `prompts/<案件名>.md` に追記し、
  再現できるようにしておく。

## リアルさのチェックリスト

生成結果をユーザーに見せる際、以下の観点で気づいた点を日本語で添える。

- 顔・手指・歯・目線に破綻がないか
- 肌の質感・髪の動きが自然か(CG っぽさ、プラスチック感がないか)
- 服のシワ・なびき・素材感が動きと一致しているか
- 商品(衣装・小物)の色・ロゴ・形が参照と一致しているか
- 足元の接地、影、ライティングが背景と合っているか

## フォルダ構成

```
realistic-human-video/
├── CLAUDE.md          # このファイル
├── prompts/           # 企画書・プロンプト・生成ログ(コミット対象)
├── blender/           # Blender 用 Python スクリプト(.blend・レンダリングは管理外)
└── assets/
    ├── source/        # 商品写真・人物写真・Blender レンダリング(管理外)
    └── output/        # Higgs Field の生成物(管理外)
```

## 権利・倫理

- 実在の人物の写真・顔を使う場合は、本人の同意が取れているものだけを対象とする。
- 有名人・著名人に似せた人物、未成年に見える人物の生成は行わない。
- ブランドのロゴや商品は、権利者の許諾があるもの・自社商品のみを使う。
- AI 生成であることの表記が配信先で求められる場合は、それに従う。
