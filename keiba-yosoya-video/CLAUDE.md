# CLAUDE.md(競馬予想屋 集客動画プロジェクト)

このファイルは、Claude Code が `keiba-yosoya-video/` フォルダで作業する際のガイドです。
ルートの `CLAUDE.md`(Higgs Field 全般の運用ルール)も併せて適用され、内容が
重なる場合はこのファイルの記述を優先します。

## 言語

- ユーザーへの返答・説明・確認はすべて **日本語** で行うこと。
- ファイル内のコメントやドキュメントも原則日本語で書く(Higgs Field に渡す
  生成プロンプト自体は、精度のため英語で書いてよい。その場合は日本語訳を併記する)。

## プロジェクト概要

Higgs Field(MCP ツール群: `mcp__higgs_field__*`)を使い、**AI で生成したリアルな
人間が登場する動画**を制作するプロジェクトです。

最初のテーマは **「競馬の予想屋をしている老人」の予想を受け取ってもらうための集客動画**。
視聴者に老人の予想(LINE登録・プロフィールリンク・有料/無料予想ページ等)へ
誘導することをゴールとします。

- 主な配信先: TikTok / Instagram Reels / YouTube Shorts(縦型ショート動画)
- 尺の目安: 15〜60秒
- アスペクト比: 基本 `aspect_ratio: "9:16"` を明示する

## 🚨 最重要ルール: 生成前に必ず許可を取る

**Higgs Field で動画・画像・音声を作成する前には、必ずユーザーに許可を取ってから
作成に入ること。** 例外はない。

- 対象: `generate_image` / `generate_video` / `generate_audio` / `*_batch` /
  `execute_preset` / `ai_influencer_generate` / `upscale_*` / `outpaint_image` /
  `reframe` / `remove_background` / `motion_control` / `dubbing` / `voice_change` /
  `create_voice` など、生成・加工・課金・処理時間が発生するすべてのツール。
- 許可を取る際は、以下をチャットで提示してから「実行してよいですか?」と確認する:
  1. 何を作るか(例: 老人キャラクターの参照画像 4枚)
  2. 使うモデル・ツールと主要パラメータ(アスペクト比・尺・枚数)
  3. プロンプト(要約で可)
  4. 想定コスト(可能なら `get_cost: true` でプレフライトした結果)
- ユーザーの「OK」「お願いします」など明確な承認を得てから実行する。
  1回の承認は、その時提示した内容に対してのみ有効。内容を変えて再生成・追加生成する
  場合は、改めて許可を取る。
- クレジット節約のため、可能な限り `use_unlim: true` を使う。無制限枠が使えない旨が
  返ってきた場合は、**「クレジットを消費する形になるがよいか」を改めて確認**してから進める。
- 課金を伴わない準備作業(`get_workflow_instructions`、`models_explore`、
  `get_presets` の閲覧、`balance` の確認、`media_upload_widget` など)は確認なしで
  行ってよい。ただし判断に迷う場合は確認を取る。

## 登場人物の設定(谷上シリーズ)

現在の制作対象は、king万グループで競馬予想を担当する **谷上** のストーリー動画シリーズ。
企画・人物設定・台本・プロンプト・確認事項は `tanigami/` フォルダにまとめてあり、
**人物や表現の判断は `tanigami/character.md` と `tanigami/concept.md` を優先する**。

- 谷上は実在の予想担当者。本人の写真・声の使用許可が確認できるまでは、
  「谷上をモデルにしたフィクション表現」(`character.md` の仮デザインA)で制作し、
  本人に似せた顔や声の複製は作らない。
- 実際の経歴・年数・的中実績・収支・習慣・過去のエピソードは作らない。
  確認が必要な項目は `tanigami/fact_check.md` に記録し、確認が終わるまで事実として扱わない。
- AI 生成・再現の映像を、本人の実際の映像だと誤解させない。

### 人物の一貫性を保つ方法

- まず `character-sheet` ワークフローで参照シート(複数アングル・表情)を作る。
- 作った人物は `show_reference_elements` で **参照エレメント** として登録し、
  以降のカットで使い回す(即時利用可・主要モデルで使える)。
- さらに同一人物の写真が 5〜20枚そろえば、`show_characters`(Soul)で
  トレーニングし `soul_2` / `soul_cinematic` でより高い一貫性を狙う選択肢もある。
- 生成に使ったシード・参照ID・プロンプトは `prompts/` に記録し、再現できるようにする。

## リアルな人間動画を作るためのポイント

- 画像生成プロンプトには、肌の質感(シワ・毛穴・シミ)、自然光、
  スマホ撮影風・ドキュメンタリー風などの具体的な撮影条件を書く。
  過度に整った「AIっぽい」顔を避ける。
- 動画化はまず静止画(キーフレーム)を作って承認をもらい、それを元に
  image-to-video で動かすと失敗が少ない。
- しゃべるカットはリップシンク/音声付き生成に対応したモデルを
  `models_explore({ action: "recommend" })` で選ぶ。モデル名は憶測で決めない。
- 手元(赤ペン・新聞をめくる手)は崩れやすいので、寄りのカットは慎重に確認する。
- 声は `list_voices` で既存ボイスを確認し、合うものがなければ `create_voice` を検討する
  (いずれも生成系に当たるものは事前に許可を取る)。

## 制作フロー

1. **企画**: 訴求・ターゲット・CTA(誘導先)をユーザーと決め、`docs/brief.md` に書く。
2. **台本**: 冒頭2秒のフック → 老人の一言 → 実績・信頼感の演出 → CTA の構成で
   `prompts/script_XX.md` を作る(後述の表現ルールを守る)。
3. **ワークフロー確認**: 複数ステップの動画制作なので、生成前に必ず
   `get_workflow_instructions`(引数なし)でカタログを確認し、該当するもの
   (例: `ugc-review-video`、`character-sheet`、`subtitles`、`thumbnail-generation`)を
   ロードする。存在するワークフロー名は毎回カタログで確認する。
4. **キャラクター作成**: 参照シート → 参照エレメント登録(**生成前に許可**)。
5. **カット生成**: キーフレーム画像 → 動画化(**各生成前に許可**)。
6. **仕上げ**: 字幕(`subtitles`)、サムネイル(`thumbnail-generation`)
   (**各生成前に許可**)。必要に応じて `virality_predictor` でフックの強さを確認する。

## 集客動画の表現ルール(コンプライアンス)

競馬・ギャンブル関連の集客は規制やプラットフォーム規約が厳しいため、以下を守る。
台本やプロンプトを作る段階でチェックし、抵触しそうな場合はユーザーに指摘する。

- **的中・利益を保証する表現をしない**: 「必ず当たる」「絶対儲かる」「元本保証」
  「確実に勝てる」などは使わない(景品表示法・特定商取引法上の問題になり得る)。
- **根拠のない実績を出さない**: 的中率・回収率・獲得金額などの数字は、ユーザーが
  根拠資料を持っている実数のみ使い、出典を `docs/` に残す。架空の的中実績や
  架空の口コミ・利用者の声を作らない。
- **AI生成であることを明示する**: 動画内と投稿文に「AI生成映像/演出を含みます」等を表記する
  (TikTok / Instagram / YouTube の AI 生成コンテンツ開示ルールにも従う)。
- **未成年への配慮**: 「馬券の購入は20歳から」の注意書きを入れる。未成年を
  ターゲットにした演出をしない。
- **商標・肖像権**: JRA 等の団体ロゴ、実在の競馬場の看板、実在の騎手・馬主・
  有名人の顔や名前を生成物に入れない。実在の馬名を使う場合はユーザーに確認する。
- **プラットフォーム規約**: ギャンブル関連広告は広告出稿時に審査や地域制限が
  あるため、広告として配信する場合は事前に各プラットフォームの規約確認を促す。

## フォルダ構成

```
keiba-yosoya-video/
├── CLAUDE.md          # このファイル
├── tanigami/          # 谷上シリーズ(concept / character / season1 / episode01 / ai_prompts / fact_check)
├── docs/              # 企画書(brief.md)、キャラクター設定(character.md)、実績の根拠資料メモ
├── prompts/           # 画像・動画生成プロンプト、台本、シード・参照IDの記録
└── assets/
    ├── source/        # 参照画像などの素材(git 管理外)
    └── output/        # 生成された動画・画像(git 管理外)
```

- 生成物(動画・画像・音声ファイル)は git 管理対象外(ルートの `.gitignore` で除外済み)。
  リポジトリには台本・プロンプト・設定などのテキストのみをコミットする。
- 必要になったディレクトリは作業時に作成してよい。

## 確認できていないことを、確認したように言わない(ユーザー指示・2026-10-20)

- Higgs Field のアップロード画面から受け取った画像・生成した動画や画像は、この環境からは中身を見られない(Higgs Field の CDN に接続できない)。
- 見ていないものについて「参考にした」「合わせた」「反映した」と言わない。見ていない場合は、その時点で「中身を見られていない」とはっきり伝え、チャットに直接貼ってもらうなど確認する方法を提案する。
- 参考写真はチャットに直接貼ってもらい、内容を具体的に書き出してからプロンプトに使う。
