# CLAUDE.md — 企業PR・紹介動画プロジェクト(リアル人物 AI 動画)

このフォルダは、Claude Code が **Higgs Field**(MCP ツール群: `mcp__higgs_field__*`)を使って
**企業案件の獲得につながる、本格的な AI 動画**を制作するための作業場所です。
このフォルダ内で作業するときは、ルートの `CLAUDE.md` に加えて本ファイルの内容に従うこと。
両者が食い違う場合は本ファイルを優先する。

## 最重要ルール:生成前に必ず許可を取る

- `generate_image` / `generate_video` / `generate_audio` / `*_batch` / `execute_preset` /
  `ai_influencer_generate` / `ads_studio_generate` / `upscale_*` / `reframe` /
  `outpaint_image` / `motion_control` / `dubbing` / `voice_change` など、
  **画像・動画・音声を作成・加工するツールは、実行前に必ずチャットでユーザーの許可を取る**。
- 許可を求めるときは、以下を日本語で簡潔に提示してから「実行してよいですか?」と確認する。
  1. 何を作るか(カット番号・内容)
  2. 使用ツール / モデル
  3. 主要プロンプト(要約で可)
  4. アスペクト比・尺・枚数
  5. 想定コスト(`get_cost: true` でプレフライトできる場合はその結果)
- 「OK」「進めて」など明確な許可があるまで生成を実行しない。
  一度許可を得ても、**別のカット・別の生成は改めて確認する**(まとめて許可を得た範囲のみ一括実行可)。
- 生成時は可能な限り `use_unlim: true` を指定し、通常クレジットを消費しないようにする。
  無制限枠が使えない旨が返ってきた場合は、**クレジットを消費してよいか必ず再確認**する。
- 分析(`video_analysis_*`)・アップロード(`media_upload_widget`)・カタログ閲覧
  (`get_presets` / `models_explore` / `get_workflow_instructions` など)の課金を伴わない
  準備作業は確認不要。ただし判断に迷う場合は確認を取る。

## プロジェクトの目的

- **架空の企業・ブランド**を設定し、実際の企業案件と同等クオリティの
  PR動画・会社紹介動画・商品/サービス紹介動画を制作する。
- 完成動画は **営業用ポートフォリオ**(実績サンプル)として使い、企業からの受注獲得を目指す。
- AI で **リアルな人間(出演者・スタッフ・お客様役)** が登場する、
  実写と見間違えるレベルの映像を作ることを重視する。

## 対象ジャンル

| ジャンル | 動画例 |
|---|---|
| 企業PR・会社紹介 | ブランドムービー、採用動画、代表メッセージ、オフィス/工場紹介、サービス紹介 |
| 飲食 | 店舗紹介、シズル感のある料理カット、シェフ紹介、新メニュー告知、来店客の食レポ風 |
| 美容 | サロン紹介、施術ビフォーアフター風、スキンケア/コスメ商品紹介、美容師・エステティシャン紹介 |
| ファッション | ブランドルックブック、新作コレクション紹介、ショップ紹介、試着・OOTD |
| その他 | ホテル・不動産・フィットネス・クリニック・教育など、案件化しやすい業種全般 |

## 架空企業の設定ルール

- 企業名・ブランド名・ロゴは **すべてオリジナル** にする。実在の企業名・商標・ロゴ・
  キャッチコピーに似せない(誤認を招く表現は避ける)。
- 企画ごとに `projects/<案件名>/brief.md` に以下を書いてから制作に入る。
  - 会社名・業種・所在地(架空)・ブランドトーン(高級感/親しみやすさ 等)
  - ターゲット顧客、動画の目的(認知/採用/集客/販売)
  - ブランドカラー・フォント・NGワード
  - 配信先(Instagram Reels / TikTok / YouTube / Web サイト / 展示会など)
- ポートフォリオとして公開する際は「架空企業によるサンプル作品」「AI生成映像」である旨を
  明記することを推奨する。

## リアルな人物映像のためのガイドライン

### 出演者(人物)の一貫性
- 同じ出演者を複数カットで使う場合は、生成前に出演者を固定する。
  - `show_reference_elements`(Elements):即時利用可、複数人物OK、主要モデルで使える。
  - `show_characters`(Soul):同一人物の写真 5〜20 枚で学習、`soul_2` / `soul_cinematic` 専用。
  - 一貫したキャラ参照シートが必要な場合は `get_workflow_instructions({ workflow: "character-sheet" })`。
- 出演者ごとの設定(年齢層・雰囲気・髪型・服装・役柄)は `projects/<案件名>/cast.md` に記録する。
- **実在の人物の顔写真を使った生成は、本人の同意があるものに限る。**
  有名人・他人の写真を無断で使わない。基本は AI で生成した架空の人物を起用する。

### プロンプト作成のコツ
- 被写体・動作・場所・光・カメラワーク・レンズ・質感を具体的に書く。
  例:`手持ち風のゆっくりしたドリーイン、50mm、自然光の窓明かり、浅い被写界深度、
  肌の質感がリアル、シネマティックなカラーグレーディング`
- 人物の不自然さ(指・歯・目線・表情の硬さ)が出やすいので、
  1カットの動作はシンプルにし、短尺(数秒)のカットを繋ぐ構成を基本とする。
- 企業らしさを出すため、「清潔感」「信頼感」「プロフェッショナル」などトーンの言葉を加える。
- 作成したプロンプトは `projects/<案件名>/prompts.md` に保存し、再現できるようにする。

### モデル選定
- どのモデルが適しているか迷う場合は、生成前に `models_explore(action: "recommend")` で確認する。
  モデル名を憶測で決めない。
- 静止画(キービジュアル・絵コンテ)→ 動画化(image-to-video)の 2 段階で作ると、
  構図と人物のクオリティを管理しやすい。静止画の段階でユーザーに確認を取る。

## 制作フロー

1. **ブリーフ作成** — `brief.md` に架空企業と動画の目的をまとめる。
2. **構成・台本** — `script.md` にカット割り(カット番号・秒数・映像内容・ナレーション/テロップ)を書く。
   PR動画は 15〜60 秒、SNS 向けは 15〜30 秒を目安にする。
3. **ワークフロー確認** — 複数ステップの動画制作では、生成前に必ず
   `get_workflow_instructions` を(引数なしで)呼び、カタログから適切なワークフローを選ぶ。
   広告・UGC・マーケティング系は `show_marketing_studio_v2` / `ads_studio_*` も検討する。
4. **出演者の固定** — Elements / Soul / character-sheet で人物を準備する。
5. **キービジュアル生成**(要許可)— 各カットの静止画を作り、ユーザーに確認する。
6. **動画生成**(要許可)— OK が出た静止画を動画化する。
7. **音声・ナレーション**(要許可)— `generate_audio` / `create_voice` などでナレーション・BGM を用意する。
8. **仕上げ**(要許可)— 字幕(`subtitles` ワークフロー)、アップスケール、
   サムネイル(`thumbnail-generation` ワークフロー)を作成する。
9. **振り返り** — 使ったプロンプト・モデル・設定・反省点を `notes.md` に記録する。

## 出力形式のデフォルト

- SNS ショート動画:`aspect_ratio: "9:16"`
- 企業サイト・YouTube・展示会用の PR 動画:`aspect_ratio: "16:9"`
- 1本の企画で両方必要な場合は、どちらをメインにするか最初にユーザーへ確認する。

## フォルダ構成

```
corporate-pr-videos/
├── CLAUDE.md              # このファイル
├── templates/             # ブリーフ・台本などのテンプレート
└── projects/
    └── <案件名>/          # 例: 01-cafe-lumiere, 02-salon-aube
        ├── brief.md       # 架空企業の設定・目的
        ├── cast.md        # 出演者設定
        ├── script.md      # 構成・台本・カット割り
        ├── prompts.md     # 実際に使ったプロンプト
        ├── notes.md       # 生成結果のメモ・振り返り
        └── assets/        # 素材・書き出し(git 管理対象外)
            ├── source/
            └── output/
```

## 運用上の注意

- 返答・ドキュメントはすべて **日本語** で書く。
- 動画・画像・音声などの生成物(バイナリ)は git にコミットしない(ルートの `.gitignore` で除外済み)。
  リポジトリにはブリーフ・台本・プロンプトなどのテキスト資産のみをコミットする。
- ローカルの画像・動画をアップロードする場合は、`media_upload_widget` を使う。
- 生成結果がイメージと違う場合は、勝手に再生成せず、修正案を提示してから許可を取る。
