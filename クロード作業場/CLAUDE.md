# CLAUDE.md

このファイルは、Claude Code がこのプロジェクトフォルダ(クロード作業場)で作業する際のガイドです。

## プロジェクト概要

このプロジェクトは **ゲームの作成** を目的としています。
ジャンル(アクション・パズル・RPG・シューティング・ノベルなど)や規模は限定せず、
ブラウザで動く小さなゲームから、段階的に作り込むゲームまで幅広く扱います。

キャラクター・アイテム・背景・UI・効果音・BGM・演出用の動画などの素材は、
必要に応じて **Higgs Field**(MCP ツール群: `mcp__higgs_field__*`)と連携して作成して構いません。
ただし、下記「Higgs Field 利用ルール」を必ず守ること。

## コミュニケーション

- ユーザーへの返答・説明・質問は **すべて日本語** で行う。
- コード内のコメントも、特に指定がなければ日本語でよい。

## Higgs Field 利用ルール(最重要・ユーザー指定)

- **画像・動画・音声・3Dモデルなどを Higgs Field で作成する前には、必ずユーザーの許可を取ること。**
  - 対象: `generate_image` / `generate_video` / `generate_audio` / `generate_3d` /
    `*_batch` 系 / `execute_preset` / `upscale_*` / `outpaint_image` / `remove_background` /
    `reframe` / `motion_control` / `ai_influencer_generate` など、生成・加工を行うツール全般。
  - 許可を求める際は「何を・何枚(何本)・どのモデル/設定で作るか」を簡潔に伝える。
    可能であれば `get_cost: true` などでコストを事前確認し、その結果も添える。
  - 一度許可を得ても、それはその依頼内容に対してのみ有効。内容・枚数・設定が変わる場合は
    改めて許可を取る。
- **クレジットの消費を避ける設定を優先する**: 可能な限り `use_unlim: true`(無制限/トライアル枠)
  などクレジットを消費しない設定を使う。無制限枠が使えないとツールから返ってきた場合は、
  「クレジットを消費する形になるがよいか」をユーザーに確認してから進める。無断でクレジットを消費しない。
- 課金を伴わない準備作業(カタログ閲覧、`get_workflow_instructions`、`models_explore` での
  モデル調査、アップロードなど)は許可なしで行ってよいが、判断に迷う場合は確認を取る。
- ゲーム公開系(`publish_playable_game` / `publish_website` / `deploy_website` など)は
  外部に公開される操作のため、必ず事前にユーザーの許可を取る。

## Higgs Field でよく使う機能(ゲーム素材向け)

使う前に、該当するワークフローやモデルを毎回カタログで確認し、憶測で決めない。

| 用途 | 使うもの |
|---|---|
| ゲーム本体(Web/ブラウザゲーム)の構築 | `get_workflow_instructions({ workflow: "website-builder-flow" })` を最初に読む |
| 一貫したキャラクターの設定画(複数アングル・表情) | `get_workflow_instructions({ workflow: "character-sheet" })` |
| キャラ・アイテム・背景・UIの画像 | `generate_image`(必要に応じて `remove_background` で透過) |
| 3Dモデル(GLB)化 | `generate_3d`(画像から3Dメッシュを生成) |
| オープニング・カットシーン・PV動画 | `generate_video`(複数ステップなら先に `get_workflow_instructions`) |
| 効果音・BGM・ボイス | `generate_audio` / `create_voice` |
| モデル選びに迷ったとき | `models_explore({ action: "recommend" })` |

- 同じキャラクターを複数素材で使い回す場合は、参照エレメント(`show_reference_elements`)や
  キャラクター設定画を作って一貫性を保つ。
- ドット絵・スプライト・タイル素材などは、サイズ(例: 32x32, 64x64)と背景透過の要否を
  事前に決めてから生成する。

## 開発の進め方

1. **企画**: ジャンル・遊び方・操作方法・ゴールを `docs/` に簡潔にまとめる。
2. **プロトタイプ**: まずは仮素材(図形や単色)で遊べる最小限のものを作る。
3. **素材制作**: 必要な素材をリスト化し、ユーザーの許可を得てから Higgs Field で作成する。
4. **組み込み・調整**: 素材を組み込み、難易度・操作感・バランスを調整する。
5. **動作確認**: 実際に起動して動作を確認してから完了報告する。

- 技術スタックは特に指定がなければ、手軽に動かせる **HTML5 + JavaScript(Canvas)** や
  Phaser などのブラウザ向けライブラリを優先して提案する。別のエンジン(Unity / Godot など)を
  使いたい場合はユーザーの指示に従う。
- 既存の有名ゲームの名前・キャラクター・アート・音楽・ステージをそのまま再現したものは作らない。
  ジャンルや仕組みが似たオリジナルのゲームとして作る。

## フォルダ構成(想定)

- `docs/` — 企画書、仕様、素材リスト
- `src/` — ゲームのソースコード
- `assets/prompts/` — 素材生成に使ったプロンプト(再現用)
- `assets/images/` — キャラクター・アイテム・背景・UI画像
- `assets/audio/` — 効果音・BGM・ボイス
- `assets/video/` — カットシーン・PV動画
- `assets/models/` — 3Dモデル

実際の作業内容に合わせて調整して問題ない。

## 注意事項

- Higgs Field で生成した大きなファイル(動画など)は、必要に応じて `.gitignore` で管理対象外にする。
  プロンプトや設定など再現可能なテキストは残しておく。
- 実在の人物の写真をもとにしたキャラクター生成などは、本人の同意が取れているものだけを対象とする。
